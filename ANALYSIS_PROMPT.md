# 🎯 Анализ: Универсальный алгоритм преобразования размеров шрифтов Figma → rusttype

## 📋 Проблема

При генерации скриншотов для разных сервисов (booking, subito, wallapop, gumtree и т.д.) размеры динамических текстов **не совпадают с оригинальными макетами в Figma**:
- На Booking размеры текстов **БОЛЬШЕ** чем в оригинале
- На других сервисах подгонку делали **вручную, подбирая по пикселю на глаз**
- Каждый новый генератор требует **ручной настройки размеров**

**Нужно найти**: Универсальный математический алгоритм преобразования, который работает для **всех генераторов** и не требует ручной подгонки.

### 2. **Rusttype и Scale::uniform()**
   - **Что исследовать**:
     - Как rusttype интерпретирует `Scale::uniform(px)` - какие единицы это на самом деле
     - Как rusttype считает font metrics (ascent, descent, line_height)

     - `rust/backend/src/generator/booking.rs:28-30` - функция `pillow_size_to_rusttype()`
     - Documentation rusttype крейта

### 3. **DPI и преобразования единиц**
   - **Что исследовать**:
     - Pillow использует 96 DPI CSS pixels
     - Rusttype использует "points" (обычно 72 DPI)
     - Как это связано с множителем 1.3 (96/72 ≈ 1.333)
     - Почему этот множитель неправильный для booking

   - **Теория**:
     - CSS px: 96 DPI (web standard)
     - Typography points: 72 DPI (print standard)
     - Фактор: 96/72 = 1.333...
     - Текущий множитель: 1.3 (неточный!)

### 4. **Разница между scale=1 и scale=2**
   - **Что исследовать**:
     - Как Figma export scale влияет на размеры в PNG
     - Как координаты и размеры масштабируются при scale=2
     - Почему booking использует scale=1, а остальные scale=2

   - **Файлы**:
     - `rust/backend/src/figma.rs:127-128` - default scale = 2
     - `rust/backend/src/generator/booking.rs:485` - booking использует scale=1
     - `rust/backend/src/generator/gumtree.rs:448` - gumtree использует scale=2

### 5. **Vertical metrics и особенности шрифтов**
   - **Что исследовать**:
     - Как rusttype вычисляет baseline, ascent, descent
     - Отличаются ли эти метрики между шрифтами (Roboto, etc)
     - Как это влияет на визуальный размер текста

   - **Файлы**:
     - `rust/backend/src/generator/booking.rs:250-274` - `draw_text()` функция
     - `rust/backend/src/generator/font_cache.rs` - загрузка шрифтов

## 🧮 Гипотезы для проверки

### Гипотеза 1: Множитель неправильный
- **Текущий**: 1.3
- **Правильный**: 96/72 = 1.333... или что-то другое?
- **Проблема**: Почему работает для некоторых, но не для booking?

### Гипотеза 2: Scale экспорта важен
- Booking использует `scale=1`, остальные `scale=2`
- Это может требовать разного преобразования
- **Решение**: Использовать одинаковый scale для всех?

### Гипотеза 3: V-metrics не учитывается
- Rusttype считает размер иначе, чем visual height
- Нужен коэффициент на основе v_metrics.ascent/descent/line_gap
- **Решение**: Корректировать на основе font metrics

### Гипотеза 4: Figma экспортирует по-разному
- Разные макеты могут иметь разные DPI или масштабирование
- **Решение**: Читать DPI info из Figma JSON

## ✅ Критерии успеха

1. **Один универсальный алгоритм** - не несколько разных для каждого генератора
2. **Математически обоснованный** - не "подогнано на глаз"
3. **Документированный** - код содержит объяснение почему именно так
4. **Применен ко всем генераторам** - booking, subito, wallapop, gumtree, markt и др.
5. **Визуально совпадает с Figma** - при сравнении скриншотов размеры текстов совпадают
6. **Нет ручной подгонки** - все размеры вычисляются программно
